# AFAQ SYRIA — حزمة الموقع وربط API

## الملفات
- `index.html`: الموقع الأصلي مع إضافة لوحة إعداد عنوان API واختبار الاتصال ومزامنة السجلات.
- `worker.js`: Cloudflare Worker؛ نقاط الصحة، مزامنة بيانات الموقع إلى D1، إنشاء فاتورة NOWPayments، واستقبال IPN والتحقق من HMAC-SHA512.
- `schema.sql`: مخطط قاعدة البيانات.

## النشر خطوة بخطوة
1. ارفع `index.html` إلى مستودع GitHub Pages مكان `index.html` الحالي.
2. أنشئ Cloudflare D1 Database باسم `afaq-db` ونفّذ محتوى `schema.sql` عليها.
3. أنشئ Worker جديداً، الصق `worker.js`، واربط D1 binding بالاسم `DB`.
4. أضف Worker Secrets: `NOWPAYMENTS_API_KEY` و`NOWPAYMENTS_IPN_SECRET`. لا تضعهما في HTML أو GitHub.
5. عيّن متغير `ALLOWED_ORIGIN` إلى رابط موقعك الدقيق، مثال `https://YOUR-USER.github.io` (بدون شرطة أخيرة).
6. اربط Worker بعنوان API ثابت على نفس النطاق إن أمكن، أو اسمح بعنوان الموقع في CORS. احمِ مسارات `/api/v1/*` بسياسة Cloudflare Access. لا تحمِ `/health` أو `/api/payment/ipn` أو `/api/payment/create` بسياسة تتطلب تسجيل دخول؛ مسار IPN يجب أن يكون عاماً حتى يصل إشعار NOWPayments.
7. في إعدادات NOWPayments ضع IPN callback URL: `https://YOUR-API-DOMAIN/api/payment/ipn`. أنشئ/استخدم مفتاح IPN Secret نفسه في Cloudflare.
8. افتح الموقع > مركز API والتكاملات، أدخل عنوان Worker واضغط «حفظ العنوان» ثم «اختبار الاتصال». بعد ذلك اضغط «مزامنة البيانات».

## واجهات API
- `GET /health` — فحص الخدمة.
- `POST /api/v1/sync` — مزامنة مجموعات البيانات إلى D1 (يجب حمايته عبر Cloudflare Access).
- `GET /api/v1/records` أو `GET /api/v1/records?type=projects` — قراءة السجلات (Access).
- `GET /api/v1/payments` — سجل الفواتير (Access).
- `POST /api/payment/create` — إنشاء فاتورة NOWPayments. JSON: `{ "amount": 25, "currency": "usd", "pay_currency": "usdttrc20", "description": "AFAQ invoice" }`. يرجع `invoice_url` و`order_id`.
- `POST /api/payment/ipn` — إشعارات NOWPayments والتحقق من التوقيع.

## حدود مهمة قبل التشغيل الفعلي
- عنوان Worker الفعلي، إعداد D1، أسرار NOWPayments، وسياسة Cloudflare Access يجب إعدادها في حسابك؛ لم تُنشأ هذه الموارد من داخل الملف.
- هذا الإصدار يزامن مجموعات بيانات الواجهة الحالية إلى D1، لكنه لا يحوّل الموقع إلى نظام مستخدمين وصلاحيات متعدد الحسابات. أضف تسجيل دخول وصلاحيات قبل فتح لوحة الإدارة للعامة.
- لا تعتبر الفاتورة مدفوعة من رابط العودة أو من واجهة المتصفح؛ اعتمد فقط على IPN صالح، ويفضل الاستعلام عن حالة الدفع من NOWPayments قبل تسليم الخدمة.
- `success_url` و`cancel_url` اختياريان. اختبر أولاً في بيئة NOWPayments التجريبية إن كانت مفعلة لحسابك.
- لا يوجد تنفيذ تداول أسهم أو تحويلات مصرفية في هذه الحزمة. شاشة الأسهم الحالية للعرض/تسجيل الطلبات فقط.


## تعدد اللغات وتطبيق الهاتف
- أضيف محدد لغة إلى لوحة التحكم وصفحة الدفع: العربية، الإنجليزية، التركية، الفارسية، الفرنسية، الألمانية، الإسبانية، الروسية، الصينية، والإيطالية.
- تتم الترجمة عبر Google Website Translator؛ لذلك يتطلب عرض الترجمات اتصالاً بالإنترنت وتحميل خدمة Google الخارجية. إذا لم تتوفر الخدمة، تبقى لغة المحتوى الأصلية العربية ويظل محدد اللغة ظاهراً.
- يتغير اتجاه الواجهة تلقائياً إلى RTL للعربية والفارسية، وإلى LTR لبقية اللغات.
- أضيف `sw.js` للتخزين المؤقت الأساسي و`icon.svg` لأيقونة التطبيق. يجب رفع الملفات الخمسة مع ملفات الموقع إلى جذر GitHub Pages.
- بعد رفع النسخة، افتح الموقع عبر HTTPS ثم أعد تحميله. قد يحتاج تحديث Service Worker إلى إعادة تحميل ثانية.


## تحديثات نسخة الإصلاح والتوسعة
- إصلاح انقطاع كتلة JavaScript في دالة طباعة الفاتورة؛ كان ذلك يبتلع أجزاء من الصفحة التالية ويمنع تحميل وظائفها بشكل صحيح.
- إزالة استدعاء `afaq-enhancements.js` لأنه غير موجود في الملفات المسلّمة، بدلاً من ترك طلب ملف مفقود.
- إضافة حقائب مستقلة للتنقيب عن الذهب والمعادن، وقطاع النفط والغاز، والتجارة العامة والاستيراد والتصدير.
- تحديث إصدار ذاكرة Service Worker إلى `afaq-syria-v2` لإجبار المتصفح على استخدام ملفات النسخة الجديدة.
- تحسين زر تبديل اللغة ليستخدم محدد اللغات الموجود فعلياً.
- فحص صياغة كتل JavaScript بواسطة Node.js وفحص بنية HTML ومعرّفات العناصر. يلزم اختبار النشر النهائي على نطاق HTTPS وحساب Cloudflare الحقيقي قبل اعتماد الدفع والمزامنة.

## تنبيه تشغيلي
صور الأقسام المعروضة صور توضيحية وليست إثباتاً لمواقع أو مشاريع حقيقية. وبيانات المحافظ والأسهم المحفوظة محلياً لا تُعد حسابات استثمارية أو أوامر تداول فعلية. لا تبدأ عمليات تنقيب أو شراء أو بيع موارد طبيعية إلا بعد التحقق من الملكية والتراخيص والامتثال للقوانين المحلية والدولية.


## مصرف آفاق AFAQ BANK — المرحلة الثانية
تمت إضافة لوحة المصرف إلى `index.html` عبر `afaq-bank.js` و`afaq-bank.css`، مع إبقاء قسم محفظة العملات الرقمية منفصلاً.

### واجهات مصرف الأعضاء
- `GET /api/bank/overview` — بيانات العضو وأرصدة كل عملة وعدد الحركات.
- `GET /api/bank/transactions?limit=100` — دفتر القيود المالي للعضو.
- `POST /api/bank/withdrawals` — إنشاء طلب سحب قيد المراجعة. يتطلب `Idempotency-Key`، ولا يخصم الرصيد عند إنشاء الطلب.
- `GET /api/bank/withdrawals` — طلبات السحب الخاصة بالعضو.
- `POST /api/bank/withdrawals/{withdrawal_id}/cancel` — إلغاء طلب سحب ما زال قيد الانتظار.
- `GET /api/admin/bank/withdrawals` — قائمة طلبات السحب للمالك فقط.
- `POST /api/admin/bank/withdrawals/{withdrawal_id}/mark-paid` — تسجيل الدفع بعد تنفيذه فعلياً عبر مزود مرخص. يتطلب `ADMIN_EMAIL` يطابق بريد حساب المالك المسجل، ورقم مرجع دفع خارجي.

### الإيداع
واجهة الإيداع تستخدم `POST /api/payment/create` الموجود مسبقاً لإنشاء فاتورة NOWPayments، وتضيف الرصيد فقط عبر IPN موثّق ومطابق للطلب. نجاح إنشاء الفاتورة لا يعني أن الرصيد زاد.

### إعدادات Cloudflare المطلوبة
1. انشر ملف `worker.js` من جذر المستودع في Cloudflare Worker المستخدم بعنوان `omax-api-105a` (أو تأكد أن إعداد النشر الآلي يشير إلى هذا الملف).
2. اربط D1 باسم binding: `DB`.
3. تحقق من وجود `SESSION_PEPPER` بطول 32 محرفاً على الأقل، و`ALLOWED_ORIGIN` يساوي أصل GitHub Pages الدقيق.
4. لتفعيل إنشاء فواتير الإيداع، يلزم `NOWPAYMENTS_API_KEY` و`NOWPAYMENTS_IPN_SECRET` في Cloudflare Secrets.
5. ضع `ADMIN_EMAIL` في Worker Variables ليطابق بريد حساب المالك، حتى تعمل قائمة ومراجعة طلبات السحب.

### ما لا يزال يحتاج شريكاً خارجياً
لا توجد حالياً واجهة صرف بنكي فعلية، أو إصدار IBAN، أو إصدار/تفعيل Visa، أو تكامل مباشر مع شبكة تحويلات بنكية. واجهة طلب السحب لا ترسل حوالة إلى بنك؛ الإدارة لا تسجل الطلب Paid إلا بعد تنفيذ الصرف فعلياً بمزود مرخص. لا تدخل بيانات بطاقة أو حساب بنكي كاملة في خانة الملاحظات.
