# آفاق سوريا — الحزمة الرئيسية (إصلاح أولي لتسجيل العضوية)

## الملفات
- `index.html`: الواجهة الرئيسية الكاملة مع الحفاظ على أقسام المنصة، وتحديث تسجيل العضوية والدخول ليتصلا بخادم Cloudflare بدلاً من إنشاء حسابات محلية تجريبية.
- `worker.js`: Cloudflare Worker للعضويات والجلسات والمحافظ الداخلية والتحويلات وواجهات NOWPayments وعمليات المزامنة والتعدين.
- `schema.sql`: مخطط قاعدة D1 المتوافق مع Worker.

## ما أصلح في هذه المرحلة
1. إزالة اعتماد إنشاء الحساب وتسجيل الدخول على `localStorage` كبديل للمصادقة.
2. توصيل التسجيل إلى `POST /api/member/register` والدخول إلى `POST /api/member/login`.
3. حفظ رمز جلسة الخادم والتحقق منه عبر `GET /api/member/me` عند فتح التطبيق.
4. تسجيل الخروج عبر `POST /api/member/logout`.
5. إيقاف استدعاءات استعادة كلمة المرور الوهمية؛ تظهر رسالة واضحة بأن الخدمة تحتاج مزود بريد ومسارات خادمية قبل تفعيلها.
6. ضبط كلمة مرور التسجيل على 10 أحرف على الأقل.
7. ضبط PBKDF2 في Worker إلى 100,000 دورة لتوافق بيئة Cloudflare Workers.

## إعداد Cloudflare قبل النشر
1. خذ نسخة احتياطية من Worker الحالي ومن ملفات GitHub Pages وقاعدة D1. لا تحذف قاعدة البيانات الحالية.
2. في Worker `omax-api-105a` اربط قاعدة D1 الموجودة باسم binding: `DB`.
3. أضف Secrets:
   - `SESSION_PEPPER`: قيمة عشوائية قوية لا تقل عن 32 حرفاً.
   - `NOWPAYMENTS_API_KEY`: مفتاح NOWPayments إذا كانت مدفوعات العملات المشفرة مفعّلة.
   - `NOWPAYMENTS_IPN_SECRET`: سر IPN من NOWPayments.
4. أضف Variable:
   - `ALLOWED_ORIGIN=https://oa626114-boop.github.io` (يجب أن يطابق أصل الموقع حرفياً دون `/` أخيرة).
5. انشر `worker.js` بعد مراجعة قاعدة البيانات والنسخة الاحتياطية. Worker ينفذ إنشاء الجداول والترحيلات المتوافقة تلقائياً، ويمكن مراجعة `schema.sql` في D1.
6. ارفع `index.html` إلى جذر مستودع GitHub Pages باسم `index.html`، مع الإبقاء على ملفات الأصول الحالية مثل `manifest.webmanifest` و`sw.js` و`icon.svg` والصفحات المنفصلة الموجودة في المستودع.
7. افتح التطبيق ثم انتقل إلى «مركز API والتكاملات»، أدخل عنوان Worker المنشور كاملاً بصيغة HTTPS، احفظه، ثم اضغط «اختبار الاتصال».
8. لا تختبر إنشاء حساب جديد قبل نجاح `/health` وظهور اتصال قاعدة D1. بعد نجاحهما أنشئ حساب اختبار، ثم جرّب الخروج والدخول مجدداً.

## نقاط لم يتم تفعيلها أو إثباتها بعد
- لم يتم النشر إلى GitHub أو Cloudflare من هذه الحزمة، ولا أملك تأكيداً حياً لحالة Worker أو إعدادات D1 أو الأسرار.
- يجب إدخال عنوان Worker الحقيقي في مركز API؛ لا يمكن استنتاج النطاق الكامل من اسم Worker وحده.
- الحسابات القديمة التي أُنشئت محلياً في النسخة التجريبية لا تتحول تلقائياً إلى حسابات خادمية. لا تحذف بيانات المتصفح القديمة؛ نحتاج خطة ترحيل منفصلة وآمنة عند الحاجة.
- استعادة كلمة المرور بالبريد غير مفعّلة حتى إعداد مزود بريد وإضافة مسارات رموز مؤقتة ومحدودة المحاولات.
- بطاقات الدفع وPayPal وPapara ليست مفعّلة في Worker الحالي. NOWPayments فقط عند ضبط المفاتيح واعتماد الحساب لدى المزود.
- الأرصدة الداخلية ليست أموالاً مصرفية ولا IBAN حقيقياً. لا تستخدمها لأموال حقيقية قبل شريك مالي مرخص ومراجعة الامتثال.
- بعض أقسام الواجهة ما زالت محلية/تجريبية؛ توصيل جميع نماذج الأقسام بمخزن D1 ومراجعة الصلاحيات هي المرحلة التالية، ولا تعني هذه الحزمة أن كل العمليات أصبحت إنتاجية.

## الاختبارات المحلية التي أُجريت
- فحص صياغة جميع كتل JavaScript المضمنة في `index.html` باستخدام Node.js.
- فحص صياغة `worker.js` باستخدام Node.js بوضع ES module.
- تنفيذ `schema.sql` على SQLite محلياً للتحقق من صحة أوامر SQL الأساسية.
- هذه اختبارات صياغة محلية فقط، وليست اختبار نشر أو اتصال حي.
